Critical Information Disclosure Bug in Government Site

Debug mode left enabled on yukti.mic.gov.in — leaking source code, environment details, Git commit hashes, and system internals to anyone who triggered an API error.

The Bug

The proof of concept here is about as simple as it gets: visit one of the site's API endpoints and send a GET request where a POST is expected. The server throws an error — and because debug mode is enabled in production, that error response leaks a significant amount of internal detail.

What was exposed on every error response:

  • Source code snippets surrounding the error
  • Current environment configuration
  • Debug version and system version strings
  • Git commit hash of the running build

None of this should ever be visible to an unauthenticated public request on a live government platform.

Initial Report to CERT-In

To: incident@cert-in.org.in
Subject: Information Disclosure Bug on https://yukti.mic.gov.in/

Greetings,

I'm writing to report an information-disclosure vulnerability on https://yukti.mic.gov.in/.

The site currently has debug mode enabled in production, which is leaking internal details including code snippets, environment configuration, system version strings, and the Git commit hash of the running build. It is also exposing parts of the source code that triggered each error. This information should not be publicly visible on a live platform.

CERT-In Response

The bug has since been fixed. Simple to find — but looking at what was being leaked, the potential impact was anything but simple.
