Public Directory Exposure on Government Website

How an open /emarketplace/ directory on phdcci.in led to a downloadable WordPress backup with database credentials inside.

Target

Website: https://phdcci.in
Vulnerable URL: https://phdcci.in/emarketplace/

Discovery

While conducting security research using search engine indexing queries, I discovered that the /emarketplace/ directory on phdcci.in had directory listing enabled. The directory contents were publicly browsable, indexed by search engines, and accessible without authentication.

Under normal server operation, standalone PHP files like wp-config.php execute server-side and do not display source code in response to browser requests. However, residing within the open directory was a compressed archive: custom (2).zip.

Downloading and inspecting the archive revealed a full backup of the WordPress installation. Because the archive contained raw source files, configuration files could be inspected directly in plaintext without server execution.

Steps to Reproduce

  1. Navigate to https://phdcci.in/emarketplace/ — a full directory listing is returned without authentication.
  2. Locate and download the backup archive custom (2).zip.
  3. Extract the archive locally.
  4. Inspect wp-config.php in a text editor.

The configuration file contained plaintext database credentials, host information, and WordPress cryptographic authentication salts, representing a severe information disclosure vulnerability.

Disclosure & Response

The vulnerability was formally reported to CERT-In. Following the disclosure, CERT-In coordinated with the site administrators, who promptly remediated the issue by disabling directory listing on the web server and removing the exposed backup archive. In accordance with responsible disclosure protocols, all downloaded testing files were securely erased.
